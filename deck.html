Rebuild History
Four rebuilds.
Each one a failure that named a layer.
Every architecture below is a *result* of a broken assumption in the one before it. The stack that survives is the one earned by failures.
01
Prompt-and-hope
Ask Claude, paste result somewhere. No memory. Every session started cold. The corrections I made yesterday were gone by tomorrow. Broke on: zero continuity — same mistakes on repeat.
2024 → early 2025
02
Skills + Rules (OpenClaw v1)
First real system — playbooks, skills, rules in a Git repo. Multiple agents. But knowledge lived in AI-tool state (Claude Desktop, Claude Code, Cursor separately). Switch tools → start over. Broke on: tool lock-in. Portability was theoretical, not real.
mid 2025
03
vince-agents repo + MCPs
One Git repo. Every runtime reads from it. Custom MCP servers expose it. Cloudflare tunnels for remote access. Portability solved. But state wasn't loaded — sessions re-invented instead of loading canonical state. Broke on: the Klaviyo Path A incident — I built a 7-property schema over an existing 12-property test batch because I searched the repo but never queried Klaviyo itself. 90 minutes wasted, migration required.
late 2025 → mid 2026
04
Obsidian-first, doctrine-as-code
Obsidian as the persistent knowledge layer, per project. `Projects/{Active,Completed,Archived}/<slug>/README.md` as source of truth. Hard-rule memory forces Step-0 = read the README + live external state before any action. LibreChat trialled + torn down when the API/subscription trade-off didn't pencil. Runtime bridged to Axis (Windows workstation) over Tailscale SSH. Where we are: a system that can't repeat the Path A failure because state has to be read to be forgotten.
2026-07 → live

MODE 02
Evaluative

Hard-rule memories. Project lifecycle rules. Writing & thinking doctrine. plan-first. session-start-checklist.

Generic agent stacks collapse all three into "context." Atlas separates them because each has different ownership, different maintenance, and different failure modes.

SELF-EVOLVING
Layer 03 · Descriptive Mode
Context discipline.
Load state before you act.
The Klaviyo Path A failure — the exact reason this layer exists as its own discipline, hard-enforced by memory that fires every session.
THE INCIDENT
2026-07-29. "Roll it out to all other customers in Klaviyo."

The agent searched the repo, found `outputs/klaviyo-sync/`, built a fresh 7-property schema, and pushed to 25 profiles.

Problem: a 12-property schema from an earlier test batch already existed on those profiles. The repo didn't know. Only Klaviyo itself knew.

Cost: 90-minute Path A migration to reconcile the two schemas. Preventable.
THE HARD RULE (NOW LOADED EVERY SESSION)
STEP 0Read Projects/Active/<slug>/README.md
STEP 1Fall through to canonical outputs
STEP 2Inspect the live external state (Klaviyo, BQ, Rill, Xero, GitHub)
STEP 3Announce loaded state as the first sentence of the reply
STEP NSave the summary back to the README before the session ends
Trigger: any `[project]` prefix, any known project name, any implicit "back to X" phrase. The rule cannot be silently skipped — announcing the loaded state exposes wrong project matches BEFORE any action.
Layers 08–09 · Evaluative Mode
Taste + destination gates.
Nothing ships without a standard check.
Descriptive says what's true. Evaluative says what's worthy. These layers sit between the runtime and the delivery — they filter what the founder actually sees.
TASTE GATE
Does it meet
my standard?
Every creative output — visual, copy, deck, campaign — passes through a taste gate before it reaches Vince. Loads brand references, identity anchors, Pinterest board analyses. Fails loud when work drifts.
Anchors: Rollie brand bible · ALD lifestyle · Nike storytelling · Go-To irreverence · Oatly self-aware humour.
DESTINATION GATE
Is this the
right thing to ship?
The ceiling check. Runs at every deliverable handover: after taste-gate, before presenting. Names the tier / distance from ceiling / next-step to close the gap. Nothing hides in "good enough."
Doctrine: Destination Delta — every handover ends with tier · distance · next step · closed-or-ledgered.
Prescriptive Mode
Doctrine as code.
Rules that fire before the agent thinks.
Hard-rule memories load into every session's hot cache. Prescriptive rules that shape how work happens — not what it produces.
01
Load state before you act
On any project reference, read Obsidian README → canonical outputs → live external state, in that order. Announce loaded state as first sentence.
02
Save state before you leave
Every substantive turn ends with a README update: `last_touched`, `Current state`, `Next action`, `Recent activity` bullet.
03
Project lifecycle rules
What counts as a project · when to auto-create · Active→Completed (shipped + resolved next-action + 30-day quiet) · Completed→Archived (90-day no-touch or superseded).
04
Vince Writing & Thinking Doctrine
First-person Vince writing: don't communicate conclusions — communicate the journey. Preserve intermediate mental steps. Discovery over persuasion. "I don't arrive at insights — I uncover them."
05
Ceiling scan · Destination delta
Session-start checkpoint 5 (mandatory). Pre + post execution gap scan. Every handover names the ceiling and the delta from it.
06
Silent fallbacks are incidents
Every `except: return default` logs the reason. Failing quiet is worse than failing loud. Applied across every scheduled job and MCP.
Doctrine files live in Obsidian at the root of each vault. Memory files sync into every Claude session's hot cache. Both authoritative.

Reliability & Observability
Every failure named.
Every recovery automated.
Each self-healing daemon exists because a specific failure happened. Nothing here is defensive-in-general — everything is defensive-against-something-that-broke.
145 orphaned claude-code processes ate 14 GB→reap-stale-claude-code · hourly launchd
Rill silently down for 60+ hours, page 18 stale→rill-recon-keepalive · KeepAlive=true
Klaviyo hash drift → full 53k re-push nightly→days_since_last_order excluded from delta hash
Mac slept when Claude Desktop crashed→caffeinate-forever daemon (independent of app)
Mongo/LibreChat data at risk on nightly failure→mongodump · 14-day retention rotation
Silent try/except fallbacks hiding errors→Hard doctrine: every fallback logs reason
Klaviyo Path A: state loss on re-entry→Obsidian-first load rule · unbypassable
Observability is thin (routing logs, per-job logs). Next investment on this rail: unified per-project telemetry surface.
